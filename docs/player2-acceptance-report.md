## 未通过项与复现步骤

### P1-01：无关用户可以读取他人的订单详情（原有问题）

1. 验收卖家发布并审核通过商品，由验收买家下单。
2. 使用第三个、与该订单无关的普通用户 token。
3. 请求 `GET /order/detail/{订单ID}`。

预期：拒绝访问（403/404），不返回订单数据。

实际：HTTP 200、业务码 200，返回订单详情。接口仅验证 USER 角色，`getDetail` 没有核对当前用户是否为买家或卖家。

风险：订单详情可能包含买卖双方、收货信息和交易信息，属于合并前应处理的权限问题。本次只使用新建验收订单复现，未读取其他人的真实订单。

定位：`api/src/main/java/com/example/controller/OrderController.java:180`；`api/src/main/java/com/example/service/impl/OrderServiceImpl.java:154`。

建议：将当前用户身份传入查询服务，按买家/卖家归属校验；管理员查询另走明确授权路径。补充第三方用户、未登录、买家、卖家的接口测试。

### P1-02：库存还有剩余时商品被提前下架（原有问题）

1. 发布库存 3 的商品并审核通过。
2. 买家购买 2 件。
3. 查询商品详情。

预期：库存为 1，商品仍为审核通过/可购买状态（1）。

实际：库存为 1，但状态已经变为下架（3）。

定位：`api/src/main/resources/mapper/ProductMapper.xml:228`。UPDATE 先扣减 `stock`，随后判断时又减一次数量，导致下架条件提前满足。

建议：基于扣减后的实际剩余库存判断售罄；补测库存 1/2/3、购买数量 1/2/3、恰好售罄、不足库存及并发下单。

### P1-03：取消不限库存订单后，商品变成有限库存（原有问题）

1. 发布 `stock=0`（不限库存）的商品并审核通过。
2. 买家购买 2 件，再取消该未付款订单。
3. 查询商品库存。

预期：仍为 0，不限库存。

实际：变为 2，后续交易语义改变。

定位：`api/src/main/java/com/example/service/impl/OrderServiceImpl.java:82`、`:184`；`api/src/main/resources/mapper/ProductMapper.xml:235`。

原因：创建订单时不限库存未实际扣减，但取消时无条件归还数量；退款归还也使用同一逻辑。

建议：明确记录订单是否实际扣减库存，取消/退款仅返还实际扣减数量，并保持不限库存语义。具体实现若需要新增字段，应单独提供并测试迁移 SQL，不以测试库覆盖稳定库。

### P2-01：管理员分页提供 100 条选项，但接口拒绝（成员二新限制与原界面不兼容）

1. 管理员打开商品管理，选择每页 100 条（页面确实提供该选项）。
2. 对应请求 `POST /product/listPage`，参数 `current=1,size=100`。

预期：成功加载，或者界面不提供后端不支持的选项。

实际：HTTP 400，提示“每页最多50条”。

定位：`view/src/views/admin/ProductManagement.vue:72` 与 `api/src/main/java/com/example/pojo/dto/ProductQueryDTO.java:23`。成员二新增的 @Max(50) 与现有 `[10,20,50,100]` 不一致。

建议：统一前后端分页范围，并同时检查共用 ProductQueryDTO 的其他分页界面。

### P2-02：重复审核正常业务冲突返回 HTTP 500（新异常处理暴露旧异常码问题）

1. 管理员审核通过一件待审核商品。
2. 对该商品再次提交审核。

预期：明确的业务冲突/参数错误（例如 409/400），前端可提示刷新。

实际：HTTP 500、业务码 500。`audit` 的预期业务异常没有显式状态码；默认码为 500，新商品异常处理器将其直接用于 HTTP 状态。

定位：`api/src/main/java/com/example/service/impl/ProductServiceImpl.java:207`；`api/src/main/java/com/example/exception/BusinessException.java`；`api/src/main/java/com/example/exception/ProductExceptionHandler.java:22`。

建议：商品业务冲突使用明确错误码，对非预期异常保留 500；补测重复审核和其他非法状态转换。
