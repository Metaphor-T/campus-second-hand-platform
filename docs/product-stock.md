# 库存、售罄与重新上架

库存模式、剩余数量、上下架状态分别保存。有限库存 `stock_mode=0`，不限库存 `stock_mode=1`，历史待确认 `stock_mode=NULL`。不使用 1000000 等数量作为不限库存标记。

| 情况 | 页面显示与行为 |
| --- | --- |
| 上架中，有限库存大于 0 | 显示剩余数量，可以下单 |
| 上架中，有限库存为 0 | 显示“已售罄”，商品详情和收藏继续可见；点击购买提示售罄 |
| 上架中，不限库存 | 显示“不限库存”；数量字段固定保存为 0，但不会据此推断模式 |
| 手动下架 | 数量展示为“已下架”；原数量、模式仍保存，编辑时可查看 |
| 历史库存模式待确认 | 显示“库存待确认”，阻止购买和审核通过，卖家需明确选择模式 |

有限库存只允许 0—999999 的整数；新发布、重新上架和审核通过时至少 1 件。提交 1000000 或更大数量会被拒绝。发布表单的“不限库存”是单独的选项。

## 下单与返还

库存仍在提交订单时扣减，用版本号和数据库条件更新防止多人购买最后一件时超卖。扣到 0 后保持上架，不自动下架；待付款订单也会占用库存。

取消订单，或售后审核通过并确认实际收到退回商品后，只处理本订单实际扣减的数量，重复操作不会重复返还。仅退款不退回商品时不恢复库存。手动下架后取消订单，商品仍保持下架。

售罄商品可以确认改为不限库存并重新审核。旧订单保留原扣库事实；当前商品为不限库存时，只记录释放/退回数量，不累加数量字段。补充有限库存仍为可能的订单返还预留空间，避免超过 999999 件。历史扣库不明时记录待核对结果，不猜测增加库存。完整流程见[售后与七天期限](after-sale-flow.md)。

## 重新上架与详情访问

在“我的商品”点击“上架”会打开完整信息确认窗口。卖家确认分类、标题、价格、交易方式、图片、库存模式和数量后提交，商品进入待审核；管理员审核通过后才恢复上架。关闭窗口不会更改商品。

已下架商品允许卖家、管理员以及该商品订单的买卖双方查看；其他用户不能访问。待审核或审核拒绝商品仍只允许卖家和管理员查看。已有订单的商品禁止直接删除，以保留交易记录。

从订单详情进入商品页，返回入口为“返回订单详情”，保留原订单及买卖方页签；从收藏进入则显示“返回我的收藏”。返回目标由站内路由生成，不接受外部跳转地址。

## 已有数据库升级

1. 停止连接目标库的后端，在 DataGrip 中备份目标数据库的结构和数据。
2. 确认选择的是要升级的库。开发阶段仅选择 `campus_system_dev_test`，不得选择稳定库 `project_db`。
3. 执行 [升级说明中的库存增量](project-upgrade-20261111.md#保留原数据库增量升级)，然后重启更新后的后端。
4. 脚本增加可为空的 `product.stock_mode`。1—999999 的旧正数库存标为有限；旧零库存及异常数量保留为待确认。原数量、状态、时间和其他表数据均保留。
5. 按脚本输出的编号，在“我的商品”编辑对应历史商品，明确选择有限或不限库存。旧的已下架商品不会自动恢复上架。

脚本可重复执行，但 MySQL 的表结构修改不能通过普通事务撤销，因此仍需事先备份。首次安装到空库只执行完整 [`sql/db.sql`](../sql/db.sql)，不要用完整 SQL 覆盖已有库。

开发测试仅在独立库进行；本次稳定库在用户验收授权后备份并执行增量升级，原业务数据保留。
