# 成员一：身份与操作权限完善及验收用例

开发及测试目录为 `campus-system-dev`，数据库为独立的 `campus_system_dev_test`，数据库账号为 `campus_dev_test`。用户验收后按文件清单同步稳定项目，保留各环境自己的数据库配置、上传文件及密钥；不改动现有演示用户的密码或昵称。测试使用临时账号，结束后删除账号及其生成的头像。

## 本次完善

此前用户管理接口已添加管理员权限，个人中心也已有本人校验。本次继续处理历史入口、当前身份核验、管理员个人维护以及管理对象边界。

1. 每个受保护的 HTTP 请求校验签名、数据库中的账号状态及实际角色；角色被撤销、账号禁用或删除时，原令牌不能继续执行受保护操作。客户端的角色字段和本地菜单不能授予权限。
2. JWT 签名密钥不再写入源码，开发环境使用忽略的本机配置。登录凭据包含与当前密码状态绑定的 HMAC 校验值，不直接暴露密码或其裸散列；改密后的旧密码凭据不能通过校验。历史令牌需要重新登录。
3. WebSocket 握手、消息处理及聊天消息接收前也检查当前身份，避免通过已经建立的聊天连接继续执行操作。
4. 普通用户通过 `/user/profile` 修改自己的资料和头像，通过 `/user/profile/password` 修改自己的密码。管理员通过新增的 `/admin/profile` 与 `/admin/profile/password` 维护自己。有效写入命令均不接受目标用户 ID。
5. 旧的个人资料、头像和带 ID 的改密入口停止写入，返回 410；伪造他人 ID 仍被拒绝。旧 Service 个人写入方法删除，前端不再调用旧入口。
6. `POST /admin/register` 的注册方法及 Service 注册方法移除。由于存在 `/admin/{id}` 的其他 HTTP 方法映射，对该旧地址发送 POST 返回 405（请求方法不支持），不会创建账号。管理员仅通过已有管理员的后台新增入口创建。
7. 用户及管理员的创建、修改改用明确字段的 DTO。新增账号不接受客户端指定 ID 或角色；编辑不能顺带改登录账号、密码、头像、注册时间或角色。
8. 管理入口核对目标账号类型。`/user/...` 不允许编辑或删除管理员，避免绕过最后管理员保护；`/admin/...` 不操作普通用户。
9. 管理员删除、禁用操作先锁定管理员记录，并至少保留一名可登录管理员。原有正常的普通用户管理操作仍可使用。
10. 管理员改密弹窗增加原密码、两次新密码（8—64 位）；头像改为选择后预览，资料保存时一起提交，取消不写库。标签随标准/大字号缩放。
11. 当前登录令牌收到 401 时，前端清除登录信息和聊天连接并返回登录页；旧请求不清除刚建立的新登录，避免失效凭据残留导致登录页反复跳转。

## 接口与权限

| 功能 | 接口 | 允许身份与处理 |
| --- | --- | --- |
| 普通用户注册与登录 | POST `/user/register`、`/user/login` | 游客可用；注册身份固定为普通用户 |
| 管理员登录 | POST `/admin/login` | 验证数据库中已有管理员身份 |
| 用户管理 | `/user/add`、`/user/update`、`/user/{id}`、`/user/{id}/detail`、`/user/listPage` | 仅管理员；变更和详情核对普通用户范围 |
| 管理员管理 | `/admin/add`、`/admin/update`、`/admin/{id}`、`/admin/{id}/detail`、`/admin/listPage` | 仅管理员；变更和详情核对管理员范围 |
| 普通用户资料/头像 | PUT `/user/profile`，JSON 或 multipart | 后端登录身份确定本人；头像由实际图片文件生成 |
| 普通用户改密 | PUT `/user/profile/password` | 本人原密码、新密码、确认密码 |
| 管理员资料/头像 | PUT `/admin/profile`，JSON 或 multipart | 后端登录身份确定本人；不接受头像地址替代文件 |
| 管理员改密 | PUT `/admin/profile/password` | 本人原密码、新密码、确认密码 |
| 旧个人写入接口 | PUT `/user`、`/admin`，两者的 `/uploadAvatar` 及 `/{id}/updatePassword` | 不写数据；停用入口 410，越权目标 403 |
| 旧管理员注册 | POST `/admin/register` | 已移除，返回 405，无创建能力 |

未登录或令牌对应的账号/凭据失效返回 401，已登录但角色不足返回 403，目标不属于该管理范围返回 404，最后可登录管理员保护返回 409，参数校验失败返回 400。HTTP 方法不支持返回真实的 405，不再以 HTTP 200 掩盖该框架错误。

## 本机密钥与后续同步

本次没有数据库结构变更，不需要迁移 SQL。`api/src/main/resources/application.yml` 仅声明环境变量占位符 `security.jwt.secret: ${CAMPUS_JWT_SECRET}`。

开发副本的忽略文件 `api/src/main/resources/application-local.yml` 已设置独立随机 Base64 密钥（原始随机内容至少 64 字节），不提交、不复制。其他环境在启动前通过自己的本机配置或环境变量提供独立密钥；缺失或过短时启动失败。不要使用源码里的历史密钥或把本机密钥写进仓库。

同步稳定项目时，单独为稳定环境生成密钥并重新登录，保留其数据库配置和上传文件。不能将开发副本的本机凭据文件整份复制过去。稳定环境的实际密钥只保存在自己的忽略配置中，提交到仓库的仍是环境变量占位符。

本次完善操作权限与当前身份校验。密码存储继续兼容原项目，本次没有实施密码哈希存储迁移，也没有完整的服务端会话注销列表。退出当前页面仍清除当前浏览器登录信息；不要将本次结果理解为已实现统一会话管理或所有安全功能。

## 手动验收用例

建议使用新建的临时普通用户和临时管理员测试，避免改动演示账号；额外管理员由当前管理员在后台新增，测试结束删除。

| 编号 | 操作 | 预期 |
| --- | --- | --- |
| IP01 | 未登录调用用户/管理员增删改查接口 | 401，不执行操作 |
| IP02 | 普通用户调用管理接口或仪表盘统计 | 403；隐藏菜单与后端权限一致 |
| IP03 | 普通用户注册请求加上 ADMIN、id 等字段 | 仍创建普通用户，不能登录管理员入口 |
| IP04 | 个人中心保存请求加入他人 ID、ADMIN、封号状态 | 仅修改当前用户允许维护的字段，他人不变 |
| IP05 | 普通用户从旧资料、头像或改密接口指定他人 ID | 403，他人的资料、文件和密码不变 |
| IP06 | 使用自己 ID 调用旧个人写入接口 | 提示入口停用，不写入数据 |
| IP07 | 调用旧 POST `/admin/register` | 405，管理员表及基础用户表不新增记录 |
| IP08 | 管理员通过后台新增管理员 | 成功，服务器确定新账号身份及 ID |
| IP09 | 管理员在用户修改请求中夹带账号、密码、头像、角色、注册时间 | 这些字段不被修改，允许的昵称/联系方式/状态仍可维护 |
| IP10 | 通过用户接口修改或删除管理员 | 404，不能绕过最后管理员保护 |
| IP11 | 通过管理员接口操作普通用户 | 404，不修改目标用户 |
| IP12 | 删除或禁用最后一名可登录管理员 | 409，保留该管理员；此项由隔离单元测试验证，不在现有演示管理员上尝试 |
| IP13 | 禁用一个临时普通用户后复用其旧令牌 | 401，受保护接口不可继续使用 |
| IP14 | 删除临时账号后复用其旧令牌 | 401 |
| IP15 | 令牌角色与数据库当前身份不符，或数据库角色已撤销 | 401，不执行管理操作 |
| IP16 | 管理员自己的资料请求加入其他管理员 ID | 只维护本人，其他管理员不变 |
| IP17 | 管理员选择头像后取消 | 只在本地预览，不上传、不改资料、不删除原头像 |
| IP18 | 管理员保存头像和昵称 | 一次保存成功，导航及时更新，文件归属于本人目录 |
| IP19 | 管理员改密时原密码错误、两次新密码不一致 | 拒绝，新旧密码不被意外修改 |
| IP20 | 管理员正确修改密码 | 当前浏览器退出；旧密码令牌被拒绝，新密码可重新登录 |
| IP21 | 普通用户改密后复用旧 HTTP 令牌及聊天连接 | HTTP 401；聊天连接再次操作时以 1008 关闭 |
| IP22 | 篡改 JWT 内容、用不同密钥签名或使用旧格式令牌 | 被拒绝，需要重新登录 |
| IP23 | 宽度 1440/768/320、标准与 200% 字号打开管理员改密弹窗 | 原密码、新密码、确认密码及按钮可操作，无页面横向溢出，标签随字号缩放 |
| IP24 | 回归个人中心和校园认证页面 | 原资料编辑、头像、改密、字号及未接入认证提示正常 |
| IP25 | 浏览器带失效令牌进入个人页面 | 自动清除失效凭据并回到登录页，能够重新登录 |
